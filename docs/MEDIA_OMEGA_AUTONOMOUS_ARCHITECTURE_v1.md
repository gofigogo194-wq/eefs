## 1. Конечный результат

Программа на Windows исследует YouTube через разрешённый API, сохраняет реальные
снимки просмотров, сравнивает темы с базовыми результатами авторов и похожих видео,
создаёт ОРИГИНАЛЬНЫЕ различающиеся Shorts и длинные ролики из библиотеки материалов
с подтверждёнными правами, проверяет каждый файл, загружает PRIVATE, после
отдельного разрешения пользователя ставит в очередь YouTube, считывает фактический
результат публикации, получает собственную YouTube Analytics, обновляет стратегию
только на основе воспроизводимых данных.

НЕ гарантируется: просмотры, заработок, YPP, популярность за 1–3 месяца.
Экспериментальная частота: до 2 Shorts/сутки и 2 длинных/неделю, увеличивать
только при реальном качестве и отдельном изменении лимитов.
Нет YouTube-скачивания чужого контента, конвейера нарезок фильмов, публикаций
чужой музыки, массово одинаковых шаблонов и обхода платформенных ограничений.

## 4. Единые данные и идентичность

SQLite — единый источник состояния работы, WAL/transactions/unique keys.
Существующие базы/хэш-журнал МИГРИРУЕМ с резервной копией, не переписываем.
Все рабочие данные в неизменном Windows профиле, не в папке новой версии EXE.
Секреты OAuth отдельно в DPAPI текущего пользователя Windows.

Контракты (наименования — типы записей, не требование создавать десятки файлов):
1. ChannelConfig: channel_id, verified_at, разрешённые тематики/источники,
   SHORT/LONG, лимиты/day, лимиты бюджета, статус AUTO, версия согласия,
   часовой пояс и scopes.
2. Observation: внешний video_id, creator_id, источник API, снято UTC,
   опубликовано UTC, views и видимость пропусков. НЕ выдумывать CTR/retention
   конкурентов.
3. Opportunity: найденные ролики, score_version, evidence_ids, давность,
   confidence/coverage и expiry.
4. ContentJob: НОВЫЙ внутренний job_id для КАЖДОГО собственного ролика,
   формат, topic, creative_version и ссылка на Opportunity. Не использовать
   внешний конкурентный video_id как идентичность собственного видео.
5. SourceLicense: SHA256 оригинала, правообладатель, ссылка/тип лицензии,
   коммерческое использование, разрешённые преобразования, статус проверки.
   UNKNOWN => BLOCKED.
6. RenderManifest: final_file path, SHA256, bytes, duration, codec, resolution,
   audio, input licenses, plan_version, QC status.
7. PublicationIntent: immutable intent_id, job_id, target_channel, manifest SHA256,
   title, description, content flags (kids/synthetic), visibility PRIVATE,
   publish policy/consent version.
8. UploadAttempt: уникальная запись перед первым POST, session/status, last_ack,
   remote_video_id если известен, опасное UNKNOWN при потере ответа.
9. RemoteReceipt: фактический GET video_id/channel/privacy/schedule/observed_at;
   отдельное состояние PUBLISHED только после наблюдения PUBLIC.
10. AnalyticsSample: собственный video_id, метрика, окно времени, формат,
    источник, версия определений, missing=UNKNOWN.
11. LearningDecision: strategy_version, выборка/контроль, изменение результата,
    основания/неопределённость, rollback.
12. WorkerLease/AuditEvent: один исполняющий worker, последнее подтверждение
    активности, причина остановки, безопасные логи.

Один найденный конкурентный ролик может мотивировать несколько РАЗНЫХ наших
ContentJob; один наш ролик может иметь несколько источников исследования.
Редактирование title после UPLOAD INTENT не даёт тайно создать новую попытку.

## 5. Детальный аудит и проверка каждого этапа

### M0 — Зафиксировать и доказать текущую работоспособность (P0)
ВХОД: HEAD Candidate; текущий пользовательский Windows-профиль.
ДЕЙСТВИЕ: проверить реальную авторизацию, загрузку одного MP4 PRIVATE,
прочитать URL/канал/видимость, перезапустить и прочитать снова, проверить,
что повторная попытка того же файла НЕ создаёт дубль.
ОШИБКИ: неправильный канал, Chrome callback, устаревший токен,
REMOTE_UNKNOWN, закрытие приложения, отсутствие MP4.
ПРОХОД: GitHub CI + реальный Windows live test + повторное чтение без записи.
ЗАПРЕТ: ни одна публичная публикация на M0.

### M1 — Единый Orchestrator и база заданий (P0)
ВХОД: Observation, Opportunity, ContentJob.
ДЕЙСТВИЕ: соединить desktop, runtime, renderer, PRIVATE uploader с единой
машиной состояний, записью переходов и SQLite-уникальностью задач.
ОШИБКИ: два одновременно открытых GUI, зависшая задача, потерянный ACK,
сбой между записью и удалённым запросом, истекшая аренда worker.
ПРОХОД: fault injection в каждой границе, restart/replay, никаких двойных
POST или дублирующих журналов, старые файлы и история доступны.

### M2 — Библиотека материалов, лицензии и редакторская политика (P0)
ВХОД: собственные/явно лицензированные видео, музыка, фото, AI-сцены.
ДЕЙСТВИЕ: права привязаны к SHA256 каждого исходника, коммерческое
использование проверяется, ограничения лицензии и происхождение видны.
На реестре работают выбор, неповторяемость, защита от однотипных выпусков.
ОШИБКИ: лицензия без подтверждения, неизвестный аудиотрек, использование
кадров фильмов, искажение чужого произведения, удалённые источники.
ПРОХОД: отсутствие любого обязательного доказательства BLOCKED;
не существует автоматического «права по умолчанию».

### M3 — Исследование и отбор (P1)
ВХОД: тематики, предел search API, свежие снимки публичных видео.
ДЕЙСТВИЕ: доступный модуль scout->snapshots->intelligence; не менее трёх
наблюдений для соответствующего текущего алгоритма; сравнение с creator
baseline и peers; фиксированная версия формулы и полнота данных.
ОШИБКИ: API quota, выборочное наблюдение победителей, разные даты,
новый канал без baseline, ноль views, нет статистики.
ПРОХОД: на одном историческом наборе проверяем, улучшает ли score выбор
относительно простой стратегии свежих релевантных тем; без доказательств
никакой «умный ИИ» не получает права отбора автоматически.

### M4 — Сценарий и самостоятельное производство (P1)
ВХОД: отобранная идея, лицензированные источники, формат и бюджет.
ДЕЙСТВИЕ: формируется конкретный оригинальный editorial brief: тема,
польза/настроение, первый кадр, отличительные сцены, звук, название,
обложка, хронометраж, соотношение сторон. Создание MP4 через FFmpeg
в .partial, проверка, атомарный rename. Short и Long — разные задания.
ОШИБКИ: клишированное повторение, несовпадение обложки и ролика,
видеоряд без разнообразия, вылет FFmpeg, мало RAM/диска, silence/black,
внезапная остановка, слишком длинный рендер.
ПРОХОД: реальные вертикальные/горизонтальные fixtures, просмотр качества,
чистый звук, отсутствие повреждённых выходных файлов, контроль расходов,
ресурсный многократный Windows тест.

### M5 — Полная верификация файлов, контента и прав (P0 перед AUTO)
ВХОД: RenderManifest + реальные байты на диске.
ДЕЙСТВИЕ: SHA256, ffprobe, полный decode, длительность, fps, aspect,
аудиодорожка, громкость/clipping/silence, чёрные кадры/стыки, текст
названия, описание, thumbnail, rights manifest, kids/synthetic флаги.
ОШИБКИ: изменившийся файл, нет аудио, неверный формат, ложный PASS,
отсутствует лицензия, однотипный контент и неочевидная добавленная ценность.
ПРОХОД: намеренно испорченные ролики блокируются; невозможность
выполнения важного теста не даёт автоматического допуска.

### M6 — Приватная очередь и восстановление (P0)
ВХОД: замороженные Job+Intent+Manifest+consent.
ДЕЙСТВИЕ: атомарная локальная попытка ПЕРЕД POST, один resumable upload,
chunk ACK, журнал состояния, полученный remote ID и авторизованный
readback владельца и приватности. Перезапуск восстанавливает состояние.
ОШИБКИ: POST/PUT timeout, 308, 401, Google 5xx, неверный канал,
последний chunk доставлен, но финальный ответ потерян.
ПРОХОД: ни один неизвестный исход не приводит ко второму созданию
видео. Если серверный ID не записан, UNKNOWN остаётся в карантине
до ручного исследования: YouTube не обещает API-level exactly-once.

### M7 — Настоящее расписание и публичный выпуск (P0)
ВХОД: PRIVATE_CONFIRMED видео, отдельное согласие пользователя,
проверка обработки YouTube, будущая дата в UTC, политика частоты.
ДЕЙСТВИЕ: status.publishAt при privacyStatus=private; readback времени
и канала; сервер YouTube самостоятельно запускает публикацию по времени.
После наступления срока реальный GET проверяет PUBLIC.
ОШИБКИ: время в прошлом (сразу опубликует!), часовой пояс, Content ID,
изменение OAuth scopes, запрещённая видимость, занятая очередь,
проблемы обработки YouTube.
ПРОХОД: explicit authorization, dry-run, private soak, ОДИН согласованный
настоящий schedule с доказанной PUBLIC-видимостью. До M7 никакого AUTO PUBLIC.

Текущий набор OAuth youtube.readonly + youtube.upload НЕ ДОСТАТОЧЕН для
videos.update: потребуется новая минимально необходимая область доступа,
например youtube.force-ssl, и явное согласие на M7. Не требовать её заранее.

### M8 — Своя YouTube Analytics (P1)
ВХОД: подтверждённый remote_id собственных роликов.
ДЕЙСТВИЕ: отдельное право yt-analytics.readonly; окна 24/48 часов,
7/28 дней; по форматам views, engaged views (если доступно), watched
minutes, average duration/percentage, подписки и retention где
API предоставляет. Вся статистика содержит время измерения.
ОШИБКИ: задержка/пересмотр метрик, недоступные комбинации,
отключение OAuth, неполная выборка, конкуренты без закрытых метрик.
ПРОХОД: недостающая метрика UNKNOWN, не ноль; фиксация версии схемы,
реальный запрос и сверка нескольких роликов с аналитикой YouTube Studio.

### M9 — Настоящее обучение на результатах (P1)
ВХОД: AnalyticsSample, версия creative/editorial/publishing policy.
ДЕЙСТВИЕ: отдельные когорты Shorts/Long; сравнение с простым baseline;
средние и медианные результаты, вариативность, факторы, повторяемость.
Изменения ограничены согласованными параметрами и версионированы.
ОШИБКИ: «один вирусный ролик значит решение найдено»,
ложная корреляция, смешение Shorts с Long, отсутствие контрольных работ.
ПРОХОД: воспроизводимый replay, известный размер выборки, причины,
неопределённость, возможность откатить стратегию.

### M10 — Надёжная автономная эксплуатация (P1)
ВХОД: подтверждённые M0..M9 + пользовательские лимиты.
ДЕЙСТВИЕ: один локальный worker, ограниченная очередь, арендование задач,
проверка сети/диска, штатный STOP, обновление токена, автоматический
readback, журнал ошибок; 24–72 часа soak с искусственными сбоями.
РЕЖИМЫ: RESEARCH_ONLY -> CREATE_DRAFTS -> PRIVATE_AUTO ->
SCHEDULE_AUTO (последний OFF по умолчанию и требует consent).
ОШИБКИ: sleep Windows, restart, сеть, лимиты API, нет лицензированных
исходников, по ошибке повторный upload.
ПРОХОД: после restart система не теряет задания, не публикует дубли,
не превышает лимиты и выводит понятное действие пользователю.

## 6. Межслойная матрица отказов

| Разрыв | Детектор | Реакция | Запрет |
|---|---|---|---|
| OAuth -> другой канал | channels.mine readback | BLOCK | fallback на другой канал |
| Токен истёк | refresh + scopes | REAUTH_REQUIRED | слепая загрузка |
| Journal повреждён | цепочка хэшей/схема | HALT, backup | переписать события |
| GUI и worker одновременно | SQLite lease + UNIQUE intent | один исполнитель | два POST |
| FFmpeg -> неполный MP4 | hash, probe, decode | BLOCK, partial cleanup | загрузить файл |
| Исходник без прав | source manifest | BLOCK | считать YouTube URL лицензией |
| POST outcome unknown | attempt ledger + quarantine | read-only/manual | новый POST |
| PUT финал потерян | ACK + unknown | read-only/manual | повторная вставка |
| Нет video_id | нет безопасной привязки | manual review | объявить неудачей автоматически |
| Schedule в прошлом | UTC + safety margin | BLOCK | немедленная публикация |
| Обработка на YouTube | processing metadata | ждать/диагностировать | считать видео опубликованным |
| Analytics пустая | explicit UNKNOWN | не учить на пробеле | считать нулём |
| API rate limit | quotas with source and reset | pause | обход через новые проекты |
| Диск/питание | health/lease/restart | recovery | терять журнал |

## 7. Особо важные проблемы текущего кода

**P0**: desktop.py отдельно делает поиск, render и PrivateUpload, а
orchestrator.py отдельно поддерживает план, ассеты и dry-run. Соединение
нельзя подменять фальшивым вызовом или дополнительным Publisher.

**P0**: реальный PrivateUpload сейчас защищает повтор на основании
channel_id + SHA256, но это ещё не сквозной job_id/intent_id всей системы.
При потерянном финальном ответе video_id неизвестен; автоматическая
разблокировка не доказана.

**P1**: булево rights_confirmed не доказывает законных прав на КАЖДЫЙ
аудио/видеофайл; нужен реестр источников и контроль независимых доказательств.

**P1**: 100 МиБ MAX_PILOT_BYTES и decode timeout=180 s ограничивают длинные
ролики. Не повышать лимит до реальных Windows-soak и ресурсных тестов.

**P1**: YouTube Analytics ещё не подключена, а competitor CTR/retention
из публичного API не выводятся.

**P1**: Google OAuth хранится через DPAPI, а upload_attempts в ~/.media_omega.
В будущем используем один корень состояния с бесшовной миграцией старого
хранилища; не уничтожать старые маркеры.

**P2**: GUI ещё показывает старую подпись «Session only; not saved» для API
key, хотя новая версия уже сохраняет API key — нужна сверка интерфейса
и реальных возможностей.

**P2**: в docs/SIMPLE_FLOW.md ряд исторических утверждений об отсутствии
live upload/OAuth устарел; документацию исправлять только после фиксации

## 8. Обязательный контур проверки каждой версии

1. Compile/lint/unit tests для всех затронутых контрактов.
2. Integration от discovery до offline publisher на реальных FFmpeg fixtures.
3. Fault-injection ДО/ПОСЛЕ каждого SQLite COMMIT и каждого Google API write.
4. Concurrent workers + restart/resume, исторические marker и journal.
5. Windows EXE smoke + реальные 9:16 и 16:9 файлы; лимиты ресурсов.
6. OAuth scope/channel/expiry/revocation; никакие токены в stdout/логи.
7. Quota/timezone/license/synthetic/kids/publishAt failure cases.
8. Public writes НИКОГДА не выполняются в CI.
9. Реальный live-пилот только по явному разрешению и подтверждению.
10. Evidence report: что PASS, что UNKNOWN, какие P0/P1 блокеры, rollback.

## 9. Интерфейс конечного продукта

Один UI, не несколько программ. Вкладки: ОБЗОР (режим/канал/последний
результат), ИДЕИ (почему тема), БИБЛИОТЕКА (права), СТУДИЯ (предпросмотр
Short/Long), ОЧЕРЕДЬ (задача/время/status), АНАЛИТИКА (по форматам и
выборкам), НАСТРОЙКИ (OAuth/ограничения/согласие), PAUSE (запрет новых
удалённых записей).

Локальная обработка требует запущенной программы/службы Windows.
Уже подтверждённая в YouTube очередь publishAt может сработать при
выключенном ПК. STOP не может отменить уже отправленную серверу задачу
без отдельного авторизованного изменения YouTube.

## 11. Внешние API-ограничения, проверено 26.10.2026

После изменения YouTube API в июне 2026 типичные default limits:
search.list до 100 вызовов/сутки, videos.insert до 100/сутки,
общие прочие операции до 10 000 единиц/сутки. Проверить актуальные
квоты КОНКРЕТНОГО OAuth Cloud проекта перед автономным запуском.
Не использовать историческую оценку «1600 единиц за upload».

При вызове videos.update для status.publishAt требуется особый OAuth
scope (текущего youtube.upload недостаточно); устанавливаем
privacyStatus=private и дату СТРОГО в будущем.
Новая Analytics требует отдельного scope yt-analytics.readonly.
Любые публичные действия и видимость — только после явного согласия,
в рамках согласованных пользовательских лимитов.

Policy 2025–2026: массовый повторяющийся/неаутентичный контент может
препятствовать монетизации независимо от технической возможности upload.
